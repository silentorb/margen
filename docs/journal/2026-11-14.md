Since my 2026-10-31 entry where I considered moving away from hex grids, I've further explored the idea and found a possible way to move away from grids entirely.

The idea would be to define node graphs entirely by relative direction constraints, independent of distance or scale, and defer realization until as late as possible.

For example, a particular graph might have a constraint where "Node A" must be North of "Node B".  The distance could be a few feet or several miles, that would be resolved later in the generation process.

The basic algorithm would treat each constraint as a pulling force.  So many spatial conflict problems can be resolved through more distance.  For this system, distances between constrainted nodes can be as long as need be to avoid conflicts, but pulled as close as they can be without conflict.

In practice, the primary constraints would match traversable graph edges, though the system could also use constraints for secondary considerations such as aesthetics.

Not only does that model solve so many problems I have wrestled with, it unifies multiple sub domains I have fought with into the same domain and provides benefits I wasn't even looking for in this direction.  That includes:

1. Seamless scaling from high level to low level world detail (Far more seamlessly than subdividing grids)
2. Along the above point, specialized subsystems like biomes and zones are less needed, the relative approach automatically handles any number of higher to low level categorizations with the same system.
3. Reduction of incidental behavior.  Grids and most any algorithm working with them injects incidental behavior which colors the output, causing subtle algorithm changes to have wildly different output side effects.  I'm finding this direction is more pure, where what was once incidental now needs to be manually added, but can be done so in a controlled, configurable manner.
4. Better support for looping pathways
5. Better support for handling clean vertical slopes 
6. Better support for seamlessly translating from an abstract initial design to a concrete final design.  (Vision/goal-driven design)

In a way, this new system is similar to BSP (Binary Space Partitioning), except where BSP normally partitions absolute space, this is partitioning relative space.

I'm thinking of calling this new system Relative Space Partitioning.

The first version I would probably limit constraints to the four Cartesian directions.  Later versions could potentially support any angle.
